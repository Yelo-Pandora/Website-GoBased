# 初学者理论正文与缓存课程合并设计

## 状态

本文记录已经确认的理论正文改写、缓存故障课程合并和数据库重建方案。
设计基线为游客理论课程与登录弹窗实施中的未提交工作区。

## 目标

课程正文应让第一次接触后端架构的读者读得下去，也能顺着页面进入实验。
本次调整保留原有知识点和实验能力，只改变讲述方式与课程组织。

登录弹窗中的提示去掉“真实”二字。
独立的“缓存故障”课程从产品中删除，其正文并入“多级缓存”。

## 正文改写范围

以下四篇正文统一改为初学者视角：

- 单机架构
- 应用与数据分离
- 应用集群与负载均衡
- 多级缓存

每篇正文从商品查询、应用发布或资源变化等具体场景切入。
术语第一次出现时先说明它解决什么问题，再补充名称和限制。
句子尽量直接，减少机械连接词、工整排比、空泛总结和讲师式判断。

原有事实、请求链路、资源边界和实验能力不变。
课程中的实验衔接仍保留，但会缩短句子，并明确操作、配置、资源和可观察结果。

## 缓存故障内容合并

删除独立的 `cache-failures` 课程正文和内容注册。
“多级缓存”正文按学习顺序组织为以下部分：

1. 一次查询怎样经过 L1、Redis 和 MySQL。
2. 缓存键、过期时间与数据更新。
3. 增加或移除缓存层时，请求路径怎样变化。
4. 缓存穿透、击穿和雪崩分别怎样发生。
5. Redis 重启后的回源、重建和恢复过程。
6. 初学者观察实验时应关注哪些命中与回源指标。

合并时删除两篇正文中重复的 Redis 故障和恢复说明。
缓存保护策略仍属于理论内容，实验不新增布隆过滤器、互斥重建、限流或降级开关。

## 课程数据

新数据库不再写入 `cache-failures` 课程种子。
课程内容仓库、内容测试和当前操作指南删除对应独立课程说明。
已有历史设计文档不改写，由本文记录后续决定。

当前数据库里已有缓存故障阅读进度和历史实验。
用户已经确认不保留这些记录，因此不增加归档字段或数据迁移。
实施完成后执行 `docker compose down -v` 删除当前 Compose 数据卷，再重新创建服务和默认数据。

## 登录提示

登录弹窗提示改为“理论课程可直接阅读，登录后即可创建和操作实验资源。”
网站介绍和课程正文中的“真实”按上下文判断，不做机械替换。

## 测试与验收

课程内容测试不再注册 `cache-failures`，并验证“多级缓存”包含穿透、击穿、雪崩和 Redis 恢复内容。
课程目录和详情 API 不再返回 `cache-failures`。
数据库重建后，课程种子只保留合并后的“多级缓存”课程。

前端单元测试、构建、Go 测试、Go 静态检查和 Compose 配置检查继续通过。
普通 E2E 验证游客阅读、登录弹窗、理论课程和多级缓存实验。

## 非目标

- 不新增缓存保护策略实验操作。
- 不修改多级缓存实验的现有 Session、CSRF 或资源配额规则。
- 不保留旧缓存故障课程的阅读进度或历史实验。
- 不重写与本次课程内容无关的产品文案。
