# 阶段八自适应负载均衡设计

## 目标

阶段八在阶段七真实应用集群和固定权重能力之上增加自适应负载均衡。
用户可以在固定和自适应模式之间切换。
自适应模式根据实例有效容量生成相对权重，并在容量稳定后安全更新实验 Nginx。

本阶段保持现有安全边界。
浏览器不能提交原始 Nginx 配置，所有拓扑操作继续经过归属校验、CSRF、幂等和串行队列。
高频负载样本只保存在进程内存，不写入 MySQL。

## 已确认决策

* Adaptive Balancer 运行在 Platform API 中，不放入编排器。
* 每 2 秒采样一次运行中的自适应实验。
* 实例集合和有效容量连续 3 次相同后才允许应用目标权重。
* 无流量时仍按稳定容量收敛，正常情况下不超过 10 秒。
* 目标权重由有效容量约简得到。
* `100:100:30` 的目标权重是 `10:10:3`。
* 负载指标使用系数为 `0.5` 的 EWMA 平滑。
* EWMA 不参与目标权重比例计算。
* 公开控制器状态仅使用 `converging`、`stable` 和 `degraded`。
* 稳定采样、配置应用和应用后的确认都属于 `converging`，不拆分公开状态。
* 成功应用后没有额外冷却时间。
* 配置失败保留退避重试，退避不属于成功冷却。
* 切回固定模式后保留最后成功权重。

## 架构

Platform API 新增 `internal/balancer` 包。
该包提供调度器、容量算法、内存指标仓库和只读状态提供器。

调度器每 2 秒读取处于 `Running` 或 `Expiring` 且模式为 `adaptive` 的应用集群实验。
每个实验使用实例标识、运行状态和有效容量构造容量指纹。
容量指纹连续 3 次相同后，控制器计算目标权重。
内部操作指纹额外包含当前权重，用于执行前识别过期结果。
只要存在非 `running` 实例、非正容量或未完成拓扑操作，本次采样就不增加稳定计数。

目标权重与当前权重不同时，控制器向现有持久操作队列写入内部
`APPLY_ADAPTIVE_WEIGHTS` 操作。
内部操作和用户扩缩容、性能调整、权重调整及模式切换共享同一串行边界。

Operation Worker 在应用内部权重前重新校验实验模式和拓扑指纹。
校验通过后，Worker 复用编排器 `APPLY_LAB_UPSTREAM` 命令。
编排器继续负责结构化配置生成、原子替换、`nginx -t` 和优雅 reload。

只有 Nginx 应用成功后，Platform API 才更新 `lab_instances.current_weight`。
内部调整不更新 `last_effective_action_at`，因此不会延长实验空闲时间。
内部调整也不会覆盖实验快照中的最近用户操作。

## 组件边界

### 调度器

调度器拥有单个定时循环，不为每个实验创建永久 goroutine。
一轮失败只记录错误，不阻止其他实验或后续轮次。

调度器负责：

* 查询自适应实验和实例容量；
* 更新稳定采样计数；
* 计算目标权重；
* 判断是否需要创建内部调整操作；
* 清理已终止或切回固定模式的内存状态。

### 容量算法

容量算法是无状态纯函数。
输入是按实例标识排序后的正整数有效容量，输出是同顺序的相对整数权重。

算法计算全部容量的最大公约数，再用每个容量除以该公约数。
现有场景有效容量范围为 20 至 100，且按 10 递增，因此约简结果位于 Nginx
允许的 1 至 100 范围内。

示例：

```text
有效容量：100, 100, 30
最大公约数：10
目标权重：10, 10, 3
```

只有一个实例时，约简权重可以是 `1`。
Nginx 权重表示相对比例，因此这与 `100` 的路由效果相同。

### 指标仓库

Traffic Service 在验证同步批次响应后，把目标实例的负载结果交给指标仓库。
每个实验实例只保存最近时间、最新值和一个 EWMA 值。

EWMA 更新公式是：

```text
smoothed = 0.5 * current + 0.5 * previous
```

EWMA 用于前端展示稳定负载、识别持续过载和解释集群总容量边界。
它不改变由有效容量计算出的目标权重，避免请求分配结果反向放大权重抖动。

没有新流量样本时，控制器仍使用容量指纹完成稳定判断。
过期负载样本不阻止权重收敛，也不会被解释为实例不可用。

### 状态提供器

状态提供器为实验快照提供只读 `balancer` 信息。
模式为 `fixed` 时，`lab.balancingMode` 已足够表达状态，`balancer` 返回 `null`。

模式为 `adaptive` 时，`balancer` 包含：

* `status`：`converging`、`stable` 或 `degraded`；
* `targetWeights`：按实例返回当前计算目标；
* `smoothedLoads`：存在新鲜样本时返回平滑负载；
* `capacityNotice`：`cluster_overloaded`、`cluster_underused` 或 `null`；
* `lastError`：仅在 `degraded` 时返回稳定错误码和可恢复说明。

稳定采样计数和失败退避时间属于内部控制细节，不在主界面展示倒计时。

负载样本在 10 秒内视为新鲜。
最近批次发生丢弃或任一新鲜 EWMA 大于等于 `1.0` 时返回
`cluster_overloaded`。
所有实例都有新鲜样本且 EWMA 均小于 `0.2` 时返回 `cluster_underused`。
样本不足或处于中间范围时返回 `null`。

## 状态流转

开启自适应、Platform API 重启、实例集合变化或有效容量变化时进入
`converging`。

`converging` 内部依次完成稳定采样、内部操作入队、配置应用和结果确认。
当前权重已等于目标权重时不 reload，连续 3 次稳定采样后直接进入 `stable`。
配置应用成功并持久化权重后立即进入 `stable`，不增加成功冷却。

`stable` 状态仍每 2 秒采样。
实例集合或有效容量变化后重新进入 `converging`。

Nginx 校验、reload 或编排器调用失败时进入 `degraded`。
失败时保留上一份有效 Nginx 配置和数据库权重。
控制器按 4 秒、8 秒、16 秒、30 秒上限进行失败退避。
重试前重新校验模式和拓扑；重试开始时回到 `converging`。

切换到 `fixed` 后停止生成新的内部调整。
已经入队的内部操作在执行前发现模式或指纹不匹配时安全结束，不应用过期配置。

## API 与持久操作

现有 `POST /api/v1/labs/:id/actions` 增加 `SET_BALANCING_MODE`。
请求参数只允许 `fixed` 或 `adaptive`。

```json
{
  "operationId": "op-example",
  "actionType": "SET_BALANCING_MODE",
  "parameters": {
    "balancingMode": "adaptive"
  }
}
```

该动作只允许应用集群场景使用。
模式没有变化时按幂等成功处理，不产生 Nginx reload。
切换模式属于用户有效操作，会刷新实验空闲时间并显示为最近用户操作。

内部 `APPLY_ADAPTIVE_WEIGHTS` 操作不暴露为浏览器可提交动作。
其 payload 包含期望模式、拓扑指纹、目标实例和目标权重。
仓库在同一事务中检查实验状态、模式、待处理操作和当前拓扑后才允许入队。

内部操作完成时使用专用持久化路径。
该路径只更新权重和内部操作结果，不更新用户活动时间。
实验快照查询最近操作时排除内部自适应动作。

OpenAPI 合同增加模式动作参数和 `balancer` 快照结构。
未知字段、非法模式和在固定模式下提交内部动作都必须被拒绝。

## 前端交互

集群控制区增加固定和自适应模式切换。
切换继续使用现有 operation ID、CSRF 和操作轮询流程。

固定模式显示手动权重编辑器。
自适应模式隐藏或禁用手动权重编辑器，并展示每台实例的有效容量、当前权重和目标权重。

公开提示保持简单：

* `converging`：自适应调整中；
* `stable`：自适应权重已稳定；
* `degraded`：自适应调整异常，将自动重试。

前端不计算权重、不推断状态，也不决定错误恢复。
同步批次动画继续只使用真实批次响应中的目标实例和处理结果。

当总负载超过集群有效容量时，页面明确说明权重无法创造容量。
提示建议扩容、恢复实例性能或降低流量，但自由探索模式不评分，也不给出唯一答案。

## 并发与恢复

内部调整和用户拓扑操作使用相同的每实验待处理操作检查。
同一时刻只有一个会改变拓扑或权重的操作可以进入执行阶段。

调度器不得在内存状态中保存事实权重。
数据库中的模式、实例、有效容量和最后成功权重始终是恢复来源。

Platform API 重启后重新扫描数据库。
自适应实验从 `converging` 开始，重新收集 3 次稳定容量样本。
重启前的过期 EWMA、稳定计数和失败退避不会被恢复。

Operation Worker 的现有租约机制继续恢复已入队操作。
内部操作执行前的模式与指纹校验防止平台重启后应用陈旧结果。

## 错误处理

编排器和 Nginx 管理器继续使用现有稳定错误码。
配置失败统一暴露为 `NGINX_CONFIG_INVALID` 或已有编排器可用性错误码。

错误响应和快照不得包含生成的 Nginx 正文、容器内部地址、Docker 标识或命令输出。
日志可以记录实验 ID、操作 ID、目标权重和稳定错误码，但不得记录认证令牌或数据库密码。

单个实验的失败不得停止全局调度器。
切回固定模式始终保留最后成功权重，不尝试恢复进入自适应前的旧权重。

### 单元测试

* 覆盖最大公约数权重计算和单实例结果；
* 覆盖 `100:100:30` 收敛为 `10:10:3`；
* 覆盖连续 3 次稳定采样和指纹变化后重新计数；
* 覆盖目标权重未变化时不创建内部操作；
* 覆盖成功应用后直接稳定且没有成功冷却；
* 覆盖 EWMA 过滤单次尖峰但不改变容量权重；
* 覆盖无流量时仍可收敛；
* 覆盖失败退避上限和成功后的错误状态清理。

* 覆盖 Nginx 失败时数据库权重不变；

### Docker 端到端验收

1. 创建应用集群实验并扩容到三台实例。
1. 将第三台实例性能设置为 30%。
1. 停止前端自动流量，切换到自适应模式。
1. 验证 10 秒内权重收敛为 `10:10:3`。
1. 验证 Nginx 配置校验通过且真实请求仍可处理。
1. 切回固定模式并记录最后权重。
1. 再次修改实例性能，验证权重不再自动变化。
1. 重启 Platform API，验证数据库模式被恢复且自适应实验重新收敛。

最终验证运行 Go 单元测试与静态检查、前端测试与构建、Compose 配置校验、
Playwright 端到端测试和真实容器恢复演练。

## 验收标准

* 用户可以安全切换固定和自适应模式；
* 无流量时，自适应权重在正常环境中 10 秒内收敛；
* 容量 `100:100:30` 稳定后权重是 `10:10:3`；
* 权重相同时不触发 Nginx reload；
* 成功调整后没有额外冷却等待；
* 固定模式不会自动修改权重；
* 配置失败不会破坏上一份有效路由；
* 内部调整不会延长实验生命周期；
* 平台重启后能从持久状态恢复自适应控制；
* 前端只展示后端状态，不自行计算目标或结果。

## 非目标

本阶段不实现基于延迟的权重、预测控制、机器学习调度、跨主机集群、SSE、
逐请求指标持久化或面向用户的控制器参数编辑。
本阶段也不改变阶段七同步流量批次协议和结果驱动动画。
