# 场景模板补全设计

## 目标

补齐课程映射中已经声明、但编排器尚未能加载的三个实验场景模板，
使应用与数据分离、多级缓存、缓存故障可以通过同一套严格模板注册表完成创建。

## 模板边界

新增以下版本化模板：

| 模板 | 应用容器 | Redis | 用途 |
|---|---|---|---|
| `application_data_separation_scenario_v1` | `app_container_v1` | 否 | 单应用访问实验独立 MySQL |
| `multi_level_cache_scenario_v1` | `cache_app_container_v1` | 是 | L1、Redis L2 和 MySQL 回源 |
| `cache_failures_scenario_v1` | `cache_app_container_v1` | 是 | 缓存故障与 Redis 重启回退 |

三个模板均复用现有数据库、网络和 Nginx 资源模板，使用严格 JSON 解码，
并提供容量、固定权重、批次和商品种子等现有 `Scenario` 字段。
阶段 9 的缓存故障开关、TTL、失效广播和保护策略不提前扩展模板 schema，
待缓存运行时实现确定后再以向后兼容的版本化字段加入。

## 验证

模板注册表必须能够一次加载四个场景模板；三个新增模板分别引用存在的资源模板，
缓存场景必须声明 `session_redis_v1`。平台课程映射中的模板 ID 与文件名必须完全一致。

## 文档同步

SRS、SDS、MVP 实施设计、编排器指南和前端接口指南统一说明：模板是实验初始值的唯一来源，
缓存场景虽然现在可以创建资源，但缓存行为和故障控制仍属于阶段 9；前端生成流量不再经过
`traffic-generator`。

## 阶段 6 衔接

模板提交完成后，下一独立提交实现生命周期调度：增加空闲/最长截止时间、有效操作刷新、
超时销毁入队、平台重启恢复和周期性资源核对，不引入 SSE 或事件环。
