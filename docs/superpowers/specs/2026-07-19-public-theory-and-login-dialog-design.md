# 游客理论课程与登录弹窗改造设计

## 状态

本文记录已经确认的网站公开理论课程、统一登录弹窗、网站介绍页和单机架构示意图设计。
实施基线提交为 `227304c`。
本次设计文档先独立提交，用户复核后再进入实施计划。

## 背景

平台原本允许游客阅读理论知识，只要求用户在使用实验资源前登录。
当前前端在恢复会话失败后直接显示全屏登录页，阻止游客访问后端已经匿名开放的课程列表和课程详情。
这一行为来自前端页面门禁，不需要修改后端课程和实验权限。

单机架构课程目前只有文字内容。
它需要在正文末尾增加一张可响应式展示的架构示意图。
课程目录还需要在单机架构之前提供一个可点击的网站介绍项。

## 结构化要求

下一可用要求编号为 `R10`。

## 方案选择

采用前端虚拟网站介绍项和公开课程壳层方案。
该方案不修改数据库种子、课程模型或 OpenAPI 契约。

未采用将网站介绍写入数据库的方案，因为介绍不属于课程，也不应产生学习进度。
未采用拆分公开站和实验控制台的方案，因为它会形成两套导航和页面状态。

## 页面状态与数据流

页面启动后先调用 `GET /api/v1/auth/me` 尝试恢复会话。
认证成功时加载带用户进度的课程目录，并继续恢复运行中的实验。
返回 `401` 时将页面标记为游客状态，不显示错误，并继续匿名加载课程目录和默认内容。

游客首次进入网站时默认选择虚拟的“网站介绍”项。
选择普通课程后，前端调用现有 `GET /api/v1/courses/:slug` 获取 Markdown 正文。
理论正文对游客和登录用户使用同一组件和同一数据源。

游客选择实验课程时仍可看到“课程 / 实验”页签。
点击“实验”页签会打开登录弹窗，而不是切换到可操作的实验工作台。
登录成功且账号没有运行中实验时，页面保留当前课程并进入实验工作台。
账号已有其他运行中实验时，平台优先恢复该实验，以保持单用户单活动实验约束。

退出登录后不清空公开课程目录和当前理论正文。
页面停止实验轮询，将当前模式切回课程，并把用户状态改为游客。

## 登录弹窗

独立全屏登录页面将被移除。
顶部游客区域提供“登录实验”按钮。
游客点击实验页签时也打开同一个登录弹窗。

登录弹窗包含账号、密码、提交状态和现有稳定错误信息。
用户可通过关闭按钮、`Escape` 或点击遮罩关闭弹窗。
提交期间禁止重复提交，但不清空已经输入的账号。

顶部按钮打开弹窗时，成功登录后保留当前页面。
实验页签打开弹窗时，成功登录后尝试进入当前课程实验。
登录失败、限流或网络失败只在弹窗内显示，不影响课程正文。

## 网站介绍

`CourseRail.vue` 在真实课程之前显示一个虚拟的“网站介绍”目录项。
该项目使用稳定字符串选择键，不复用课程数字 ID。
它不会调用课程详情 API，也不会写入学习进度。

右侧网站介绍页说明以下内容：

* 平台用于学习互联网后端架构从简单到复杂的演进过程。
* 理论内容对游客开放，实验资源需要登录后创建。
* 推荐路线为单机架构、应用与数据分离、应用集群、多级缓存。
* 实验通过真实 Go 服务、Nginx、MySQL、Redis 和容器资源展示结果。

介绍页沿用课程内容区的排版和响应式宽度，不伪装成课程正文。

## 单机架构示意图

单机架构详情页在 Markdown 正文之后渲染独立示意图组件。
组件只在课程 `slug` 为 `standalone-architecture` 时出现。

示意图使用语义化 HTML、CSS 和现有图标，不创建图片文件，也不把 HTML 写入 Markdown。
图中展示以下请求路径：

```text
用户 -> Nginx / Web 入口 -> Go 应用 -> MySQL
```

Nginx、Go 应用和 MySQL 位于同一个“单机主机”边界中。
主机下方显示共享的 CPU、内存和磁盘资源。
故障说明指出主机故障会同时影响入口、应用和数据。

桌面端使用横向请求路径。
窄屏和移动端使用纵向请求路径，不能造成横向滚动。
示意图区域提供明确标题和无障碍说明。

## 组件边界

新增 `LoginDialog.vue`，只负责弹窗、表单和登录反馈。
新增 `SiteIntroduction.vue`，只负责网站介绍内容。
新增 `StandaloneArchitectureDiagram.vue`，只负责单机示意图。

`App.vue` 负责游客、用户、选择项、登录意图和实验恢复状态。
`CourseRail.vue` 负责渲染介绍项与真实课程项，不读取登录状态。
`CourseTheory.vue` 继续负责理论正文，并按课程标识插入附加示意图。

## 错误与边界处理

匿名 `auth/me` 返回 `401` 属于正常游客路径。
课程目录或课程详情加载失败时继续显示现有重试界面，不自动打开登录弹窗。

实验轮询期间收到 `401` 时停止轮询，清除用户会话状态，并回到当前课程理论页。
再次点击实验页签时打开登录弹窗。

登录成功后若发现账号已有其他活动实验，恢复该实验和对应课程。
登录成功后的课程或实验恢复失败时保留已加载的公开课程，并显示稳定错误。

## 测试与验收

前端单元测试验证游客认证状态不会阻止课程加载。
组件测试验证登录弹窗的打开来源、关闭行为和错误保留。

E2E 增加以下场景：

* 游客打开网站后默认看到网站介绍。
* 游客选择单机架构并读取完整理论正文。
* 单机架构正文末尾显示架构示意图。
* 游客点击实验页签后出现登录弹窗。
* 登录成功后进入当前课程实验工作台。
* 顶部登录成功后保留当前介绍或课程页面。
* 退出登录后仍可继续阅读理论课程。
* 移动端介绍、弹窗和单机示意图没有横向溢出。

现有 Markdown 安全、实验生命周期、自适应控制、缓存实验和 Swagger 边界测试继续回归。
后端课程匿名访问与实验认证测试保持不变。

## 非目标

* 不增加游客账号或匿名实验资源。
* 不修改实验 API 的 Session、CSRF 和资源配额规则。
* 不把网站介绍保存为数据库课程。
* 不创建单机架构实验。
* 不引入路由框架或拆分独立公开站点。
