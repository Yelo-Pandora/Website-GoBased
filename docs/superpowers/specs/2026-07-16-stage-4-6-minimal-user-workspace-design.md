# 阶段四至六最小用户工作台设计

## 目标

把当前 Swagger 单页改为普通学习者可以直接使用的最小实验工作台，
通过真实登录、选课、创建、观察、重置、等待过期和结束流程验证阶段四、五、六。
Swagger UI 保留为次级视图，不增加新的后端端点。

## 用户流程

1. 未登录用户看到登录表单。
2. 登录成功后加载课程列表和当前用户信息。
3. 用户选择一个可用实验课程并创建实验。
4. 页面轮询实验快照，展示创建操作、网关、应用实例、Redis 和实验状态。
5. `Running` 后显示空闲和最长时限倒计时。
6. 用户可以重置或主动结束实验，并观察最新操作状态。
7. 页面刷新后通过 `auth/me` 和 `GET /labs/:id` 恢复登录与实验状态。

## 页面结构

顶部栏包含产品名、实验/API 分段切换和用户菜单。
实验视图采用工作台布局：左侧课程列表，右侧实验状态、拓扑、生命周期和操作记录。
未创建实验时右侧显示当前课程摘要和创建按钮。

拓扑只展示阶段四至六已有事实：实验网关、应用实例、MySQL 和可选 Redis。
不加入请求小球、前端流量生成、扩缩容、性能调节或权重控制。

## API 与状态

前端 API 客户端统一使用同源请求和 Cookie，CSRF Token 仅保存在内存中。
应用启动时调用 `GET /api/v1/auth/me` 恢复会话；登录响应同样保存 CSRF Token。

创建、重置和结束请求使用随机 `operationId`。操作受理后立即刷新快照：

* 最新操作处于 `pending`、`claimed` 或 `running` 时每秒轮询；
* 实验处于 `Preparing`、`Expiring` 或 `Terminating` 时每秒轮询；
* `Running`、`Failed` 或 `Terminated` 时每 5 秒轮询；
* 页面隐藏时停止高频轮询，重新可见后立即刷新。

倒计时只根据后端 `idleExpiresAt` 和 `maximumExpiresAt` 计算显示，不修改实验活动时间。

## 错误处理

前端解析统一错误信封，显示稳定错误码和用户可读消息。
`401` 清除本地登录态；`LAB_BUSY` 保留快照轮询；网络错误不自动重复提交写请求。
创建、重置和结束按钮在请求中或实验状态不允许时禁用。

## 阶段验收映射

阶段四通过阶段五入口间接验证：真实创建和清理 Docker 网络、应用容器、Nginx 片段和实验数据库，
浏览器不能访问 UDS、Docker、MySQL 或 Lab App 内部端点。

阶段五验证创建、快照恢复、重置、主动结束、失败展示和资源清理。

阶段六验证两个截止时间、`Running -> Expiring -> Terminating -> Terminated`、
`idle_timeout`/`maximum_duration` 原因和刷新后的状态恢复。验收环境通过 Compose 环境变量
缩短时限，不在用户界面增加强制过期能力。

## 视觉边界

界面采用安静、信息密集的运维工作台风格。状态使用中性色、绿色、黄色和红色区分；
按钮使用图标和简短命令文本；卡片圆角不超过 8px。桌面为双栏，移动端变为单栏，
所有状态、倒计时和操作文本必须在 320px 宽度下正常换行。

## 验证

实现后执行：

* `npm --prefix web run build`；
* `go test ./...`；
* `go vet ./...`；
* `docker compose config --quiet`；
* 重建 Edge 前端；
* 浏览器桌面和移动视口完成登录、创建、快照、重置、结束和刷新恢复；
* 使用缩短生命周期配置验证自动过期；
* 检查无受管容器、Nginx 片段或实验数据库残留。
