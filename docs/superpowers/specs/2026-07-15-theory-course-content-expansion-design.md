# 理论课程正文扩写设计

## 目标

扩写现有五篇理论课程正文，让每篇正文达到约 1400 至 1800 字。
正文继续面向已理解 HTTP 和数据库基础概念的初学者，用自然、克制的语言解释架构变化。

本轮只调整课程文本，不修改课程 API、数据库结构、实验状态或资源编排逻辑。

## 写作方式

采用场景驱动方式。
每篇正文围绕网购平台中的一次商品查询、应用发布、容量变化或缓存故障展开。
读者应能顺着请求发生的先后顺序，看懂问题怎样出现、系统怎样处理，以及处理方案付出的代价。

保留现有一级标题、主要二级标题和参考链接。
允许在确有需要时增加少量二级标题，但不把正文拆成密集的知识点清单。

## 课程扩写范围

### 单机架构

补充一次完整商品查询在单机内经过入口、应用和数据库的过程。
说明共享处理器、内存、磁盘和网络如何造成相互影响，并用发布、备份、磁盘占满和机器故障说明恢复边界。
结尾说明团队应根据哪些迹象考虑拆分，而不把拆分描述成必然选择。

### 应用与数据分离

补充应用发布和数据库备份互相干扰的具体过程。
沿商品查询说明网络往返、连接池、超时、重试和重复写入问题。
说明职责分离带来的资源、权限和发布收益，也保留共享数据库成为新瓶颈的事实。

### 应用集群与负载均衡

用连续请求落到不同实例的过程解释轮询、加权轮询、最少连接和响应时间策略。
补充实例仍然存活但处理能力下降的场景，区分健康状态和剩余容量。
结合平台固定权重与自适应权重实验说明调整过程、稳定窗口、冷却时间和集群总容量上限。

### 多级缓存

沿一次商品详情查询说明 L1、Redis L2 和 MySQL 的命中与回填顺序。
补充多个应用实例各自持有 L1 后出现旧值的过程，以及数据库更新、Redis 删除和失效通知的传播窗口。
说明过期时间、随机偏移、条目上限和回源速度之间的取舍。

### 缓存故障

分别用不存在商品、热门商品过期、批量键同时过期和 Redis 重启描述穿透、击穿、雪崩与缓存失效。
让读者看到请求怎样从缓存回到数据库，以及限流、互斥、空值、布隆过滤和降级分别解决什么问题。
保留各类保护策略的成本，并说明实验中应观察的命中、回源、重建、等待和降级指标。

## 风格约束

正文不包含具体编程语言语法、框架配置或代码教程。
不复制参考文章的句子、代码和配图。
不使用宣传式结论、机械排比、虚假引用或为了显得亲切而加入的网络口头语。
允许自然重复必要术语，不为了避免重复而频繁更换同义词。

每段只承担一个主要意思，长短句适当交替。
尽量用具体动作和结果解释抽象概念，例如请求排队、连接等待、旧值返回和数据库回源。

## 实现边界

正文描述的平台能力必须与当前 SRS 和 SDS 一致。
尚未完成的动态实验能力应使用将来时或设计语气，不得写成已经可以操作。
单机架构仍是纯理论课程，不新增实验可用性。

五篇正文继续由 `go:embed` 编译进 Platform API。
课程 slug、文件名、返回结构和参考链接保持不变。

## 验证

完成扩写后执行以下检查。

* 每篇正文约 1400 至 1800 字。
* Markdown 标题层级和参考链接有效。
* 扫描常见 AI 套话、机械连接词和禁用句式。
* 核对文中不存在具体语言教程或未实现能力的完成式描述。
* 运行课程内容测试和 `go test ./...`。

正文修改完成后单独提交中文 commit。
提交主题使用 `docs: 扩写并润色理论课程正文`。
