# 阶段九多级缓存层级控制与故障理论收敛设计

## 目标

阶段九只保留一个可操作实验：多级缓存。

独立的“缓存故障”实验取消。“缓存故障”课程继续保留为纯理论课程，讲解缓存穿透、
缓存击穿、缓存雪崩、Redis 故障及常见保护思路，但不创建实验资源，也不承诺保护策略切换。

多级缓存实验在现有真实 L1、Redis 和 MySQL 查询链路上增加四个受限操作：

* 去除指定应用实例的 L1。
* 为指定应用实例添加空 L1。
* 真实删除当前实验 Redis。
* 使用固定模板重新创建当前实验 Redis。

用户通过改变缓存层级，观察真实请求路径、库存和回源变化。页面不提供 TTL、容量、
保护算法、Redis 命令或任意配置输入。

## 对旧设计的覆盖关系

本文覆盖阶段九旧设计中以下内容：

* 取消独立 `cache_failures` 可操作场景。
* 取消缓存穿透、击穿和雪崩的交互实验。
* 取消空值缓存、布隆过滤器、`singleflight`、Redis 互斥锁、提前续期、
  回源限流和降级策略的用户开关。
* 保留上述主题的理论课程正文。
* 将 Redis 不可用体验收敛为多级缓存实验中的 Redis 层级去除和添加。

未被本文覆盖的多级缓存基础设计继续有效，包括三台等权应用实例、每实例独立 L1、
共享 Redis、实验 MySQL、十二个商品、L1 九项 LRU、TTL、真实命中、模拟耗时和库存视图。

## 课程与实验边界

### 多级缓存

“多级缓存”课程保留可操作实验。实验默认创建：

* 三台固定等权应用实例。
* 每台实例一个独立 L1。
* 一个实验专属 Redis。
* 一个实验隔离 MySQL 数据库。
* 一个实验 Nginx 入口。

实验增加层级添加和去除按钮，但不增加自由策略编辑器。

### 缓存故障

“缓存故障”课程继续出现在知识地图和课程列表中，但 `labAvailable=false`。

课程页面只显示理论正文。它不显示创建、重置、拓扑、请求流或实验操作按钮。

正文不得再使用“后续实验将展示”“设计中的实验”“实验允许切换保护”等承诺性表述。
正文应明确这些内容用于解释工程风险与保护思路，当前平台不提供独立故障实验。

## 允许的层级组合

每台实例的 L1 状态相互独立。Redis 状态由整个实验共享。

| 目标实例 L1 | Redis | 真实查询路径 |
| --- | --- | --- |
| 开启 | 存在 | L1 → Redis → MySQL |
| 去除 | 存在 | Redis → MySQL |
| 开启 | 不存在 | L1 命中，或 L1 → MySQL |
| 去除 | 不存在 | MySQL |

允许用户同时去除三台实例的 L1 和共享 Redis。此时所有请求真实访问 MySQL。

## 单实例 L1 语义

每个 Lab App 进程维护自己的 `l1Enabled` 状态。

### 去除 L1

去除指定实例 L1 时：

1. Platform API 验证用户、实验和目标实例。
1. 控制请求通过内部 Nginx 指定实例路由到目标 Lab App。
1. 目标实例原子关闭 L1。
1. 目标实例清空现有正向 L1 条目。
1. 操作结果返回目标实例新的 L1 状态和清空 Delta。

后续请求仍可由 Nginx 路由到该实例。处理器跳过 L1，从 Redis 开始查询。

批次轨迹使用：

```json
{"layer":"l1","result":"disabled"}
```

`disabled` 不得计为 L1 miss。

### 添加 L1

添加指定实例 L1 时，目标实例启用一个空 L1。后续 Redis 或 MySQL 结果按现有规则逐步回填。

操作不影响其他实例。重复添加或重复去除按幂等成功处理，不重复产生副作用。

### 生命周期

L1 是进程内临时状态。实验重置重新启用三台实例的 L1。实例容器被重新创建时也从启用的空 L1 开始。

## Redis 语义

### 去除 Redis

去除 Redis 复用现有 `DELETE_SESSION_REDIS` COMMAND，真实删除当前实验 Redis 容器。

删除后：

* Redis 内容全部消失。
* 已有 L1 条目仍可命中，直到过期或被淘汰。
* L1 未命中请求访问 Redis 时得到 `unavailable`，随后真实回源 MySQL。
* 结果 `resolvedBy` 为 `degraded`。
* MySQL 结果只回填当前可用的 L1，不伪造 Redis 写入成功。
* Lab App `/healthz` 继续成功，避免应用实例被 Nginx 摘除。

### 添加 Redis

添加 Redis 复用现有 `CREATE_SESSION_REDIS` COMMAND，使用固定 `session_redis_v1` 模板重新创建容器。

重新创建的 Redis：

* 没有旧缓存内容。
* 不公开宿主机端口。
* 关闭 RDB 和 AOF。
* 使用原实验网络和 `lab-redis` 别名。
* 由 Lab App 现有 Redis 客户端自动重连。
* 由后续真实请求逐步回填。

重复添加或重复去除按幂等成功处理。

## 控制接口

浏览器继续只调用：

```text
POST /api/v1/labs/:id/actions
```

新增四个动作：

| 动作 | `targetInstanceId` | 参数正文 |
| --- | --- | --- |
| `REMOVE_INSTANCE_L1` | 必填 | 不允许额外参数 |
| `ADD_INSTANCE_L1` | 必填 | 不允许额外参数 |
| `REMOVE_SESSION_REDIS` | 禁止 | 不允许额外参数 |
| `ADD_SESSION_REDIS` | 禁止 | 不允许额外参数 |

所有动作验证：

* 登录与 CSRF。
* 实验归属。
* 实验状态为 Running。
* 场景为 `multi_level_cache`。
* 目标实例归属。
* `operationId` 幂等。
* 同实验操作串行。

浏览器不能提交 Redis key、Redis 命令、Docker 参数、容器名称、内部地址或配置正文。

## 指定实例内部路由

L1 动作和 L1 状态读取不能依赖 Redis Pub/Sub，因为 Redis 可能已经被删除。

实验 Nginx 为每台已知实例生成受信内部路由：

```text
/internal/instances/app-1/cache-state
/internal/instances/app-1/cache-actions
```

Platform API 根据持久拓扑生成固定目标路径。Nginx 将该路径代理到对应实例容器。

这些路由只存在于实验内部网关。Edge Nginx 不公开它们，浏览器也不能直接访问。

Platform API 获取缓存快照时，分别读取三台实例的 L1 状态，再读取共享 Redis 有界库存。
因此 Redis 不存在时仍能得到三台实例的真实 L1 状态，不依赖 Redis 中的实例摘要。

## 批次协议与快照

`CacheTraceStep.result` 增加：

```text
disabled
```

L1 快照增加稳定状态：

```json
{
  "instanceId": "app-2",
  "status": "disabled",
  "observedAt": "...",
  "entries": []
}
```

启用状态使用 `live`。实例不可访问时使用 `unavailable` 或保留较新 Delta 并标记 `stale`。

Redis 快照状态允许：

* `running`
* `removing`
* `absent`
* `creating`
* `unavailable`

Redis 不存在时不得把状态伪造成空且正常运行的缓存。

批次 Delta 继续即时更新页面，快照负责最终校正。动画完成顺序不参与状态推导。

## 前端设计

### 控件位置

不新增故障实验卡或策略面板。

每台 L1 库存卡片右上角只显示一个按钮：

* 启用时显示“去除 L1”。
* 去除时显示“添加 L1”。
* 操作中显示“正在去除…”或“正在添加…”。

共享 Redis 卡片右上角只显示一个按钮：

* 存在时显示“去除 Redis”。
* 不存在时显示“添加 Redis”。
* 操作中显示“正在删除…”或“正在创建…”。

### L1 展示

L1 去除后：

* 应用实例节点继续存在。
* L1 区域变灰并显示“L1 已去除”。
* 商品库存清空。
* 容量显示 `0/0`，不显示 `0/9`。
* 请求从应用节点直接进入 Redis 或 MySQL。

添加 L1 后显示空库存和“等待真实请求回填”。

### Redis 展示

Redis 去除后保留灰色占位节点，显示“Redis 未部署”和 `0/0`。

App 到 MySQL 的降级连线变为高亮虚线。添加成功后节点恢复为运行状态，但库存仍为空，
显示“已恢复，等待回填”。

Redis 卡片展示当前状态、商品数量、最近操作时间和恢复后的 `N/12` 回填进度。

### 动画

动画完全使用后端轨迹：

* `l1: hit`：停止在目标 L1。
* `l1: disabled`：经过应用实例并跳过灰色 L1。
* `redis: hit`：停止在 Redis。
* `redis: unavailable`：经过断开位置并继续到 MySQL。
* `mysql: hit`：到达 MySQL，再由 Delta 更新当前可用缓存层。

不同批次继续允许相互超越。

### 指标

在现有计数上增加：

* `L1 已跳过`
* `Redis 不可用`

每台实例显示最近一次真实路径。Redis 卡片显示回填进度。

### 操作期间流量

层级操作不得停止持续请求流。

操作进行时只禁用结构操作按钮，不禁用开始、停止和单批发送。用户可以观察 Redis 从
`removing` 到 `absent`、从 `creating` 到 `running` 的全过程。

## 错误处理

* 目标实例不可访问时，L1 操作失败，原状态不变。
* Redis 删除失败时，页面继续使用快照真实状态。
* Redis 创建失败时，页面保持 `absent` 或 `unavailable`，L1 和 MySQL 仍可用。
* Platform API 不向浏览器返回容器 ID、内部地址、Docker 错误或 Redis 原始错误。
* 层级操作失败使用稳定业务错误码和现有操作错误展示。

## 删除独立缓存故障场景

实施时删除：

* `configs/scenarios/cache_failures_scenario_v1.json`
* `cache_failures` 实验场景映射
* 模板注册表对该实验场景的加载断言
* Lab App、Platform API 和前端对 `cache_failures` 运行时的分支

保留“缓存故障”课程正文，但设置 `labAvailable=false`。

旧的终态实验记录可以继续作为历史摘要存在。部署前应清理仍处于活动状态的旧
`cache_failures` 临时资源；不迁移或恢复旧故障实验运行时。

## 测试与验收

### 课程与场景

* “缓存故障”课程返回 `labAvailable=false`。
* 平台不能创建 `cache_failures` 实验。
* 模板注册表不再加载 `cache_failures_scenario_v1`。

### L1

* 去除 `app-2` L1 后，只有 `app-2` 返回 `l1: disabled`。
* `app-1` 和 `app-3` 的库存与命中不受影响。
* 去除操作清空目标实例 L1。
* 添加后从空 L1 开始回填。
* Redis 不存在时仍能操作并读取三台 L1 状态。

### Redis

* 去除 Redis 后容器真实消失。
* Redis 不存在时已有 L1 仍可命中。
* Redis 不存在且 L1 未命中时真实访问 MySQL。
* 添加 Redis 后容器使用固定模板重新创建。
* 新 Redis 初始为空，并由请求逐步回填。

### 前端

* 页面只显示四个层级添加和去除按钮。
* 操作期间请求流继续运行。
* L1 disabled 和 Redis unavailable 动画来自后端轨迹。
* 快照不会用较旧状态覆盖较新动作结果。

### 回归

* 阶段七和阶段八行为不变。
* 未操作层级时，多级缓存真实命中、九项 LRU、TTL 和模拟耗时行为不变。
* 实验重置恢复三台启用的空 L1 和一个空 Redis。

## 非目标

* 不提供独立缓存故障实验。
* 不实现穿透、击穿和雪崩保护策略开关。
* 不实现空值缓存、布隆过滤器、`singleflight` 或 Redis 重建锁。
* 不允许任意 Redis、Docker、TTL、容量或缓存键配置。
* 不允许浏览器直接访问 Lab App、Redis 或内部 Nginx 指定实例路由。
