# 实验编辑状态同步设计

## 背景

实验页面定期从 Platform API 获取完整快照。新快照会替换 `trafficPolicy` 和
`instances` 等对象，即使其中的数据没有变化，对象引用也会改变。

当前流量参数和集群控制参数直接监听这些对象并重新赋值，导致用户正在编辑的内容
被普通快照刷新覆盖。受影响的控件包括：

- 每批等效订单；
- 批次间隔；
- 实例性能；
- 固定权重。

## 目标

- 普通轮询和手动快照刷新保留四个控件的本地值。
- 扩缩容真正改变实例集合后，四个控件刷新为后端当前状态。
- 负载均衡模式真正变化后，四个控件刷新为后端当前状态。
- 新实验使用新的默认值和实例实际值，不继承旧实验编辑状态。
- 后端性能或权重变化时，未编辑的控件跟随后端更新，正在编辑的控件在普通快照
  刷新中保持不变。

## 状态边界

### 普通快照刷新

实验 ID、实例 ID 集合和负载均衡模式均未变化时，刷新属于普通快照刷新。对象引用
变化、负载变化、操作状态变化以及实例运行指标变化都不构成编辑状态重置条件。

### 结构性变化

以下任一状态真正变化时重置四个控件：

- 实验 ID；
- 实例 ID 集合；
- 负载均衡模式。

扩缩容或模式切换请求失败时，上述状态没有变化，因此不重置本地编辑。

## TrafficStage

`TrafficStage` 创建时从 `trafficPolicy` 初始化每批等效订单和批次间隔。组件不再通过
策略对象 watcher 重复写入默认值。

同一实验的普通快照刷新继续复用组件并保留两个参数。实例 ID 集合或负载均衡模式
变化时，两个参数重新读取当前策略默认值。

Platform API 不保存浏览器中尚未发送的流量参数，因此这两个参数的“后端当前状态”
指 `trafficPolicy` 中的默认值，当前为每批 10 个等效订单和 250ms 间隔。

## ClusterControls

`ClusterControls` 为性能和权重分别保存两组数据：

- 当前本地编辑值；
- 上一次观察到的后端值。

普通快照刷新时逐实例协调数据：

- 本地值等于上一次后端值，表示用户没有编辑，更新为新的后端值；
- 本地值不等于上一次后端值，表示存在未提交编辑，保留本地值；
- 无论是否保留本地值，都记录新的后端值作为下一次比较基准。

实例集合或模式变化时，不执行上述保留逻辑，而是清理无效实例并把所有本地值重置
为当前实例的 `performancePercent` 和 `currentWeight`。

提交成功后，后端值会与本地值一致，该控件自然回到未编辑状态。提交失败时后端值
不变，本地值继续保留，用户可以修改或重试。

## 组件身份

`LabWorkspace` 为 `TrafficStage` 和 `ClusterControls` 分别设置带组件前缀的实验 ID
`key`。同一实验的 key 保持不变；新实验 ID 产生新的 key，使 Vue 创建全新的组件
状态。两个兄弟组件使用不同前缀，避免重复 key。

## 测试与验收

- 修改四个控件后触发手动快照刷新，值保持不变。
- 等待自动轮询后，四个控件的值保持不变。
- 扩容或缩容成功后，四个控件恢复策略默认值或实例实际值。
- 模式切换成功后，四个控件恢复策略默认值或实例实际值。
- 扩缩容或模式切换失败时，不清除本地编辑。
- 结束并新建实验后，流量参数恢复策略默认值，性能与权重读取新实验实例值。
- 现有前端单元测试、构建、单批发送调度回归和阶段七、阶段八 Playwright 验收继续
  通过。
