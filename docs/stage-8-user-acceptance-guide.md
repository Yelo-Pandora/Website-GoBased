# 阶段八自适应负载均衡验收指南

## 验收范围

阶段八完成固定与自适应负载均衡模式切换。
Platform API 每 2 秒采样一次运行中的自适应实验。
实例集合、运行状态和有效容量连续 3 次稳定后，系统按容量比例计算相对权重。

自适应控制器公开状态保持为 `converging`、`stable` 和 `degraded`。
成功调整不增加额外冷却时间。
Nginx 配置应用继续经过结构化生成、原子替换、`nginx -t` 和优雅 reload。

## 标准流程

1. 登录测试账号并创建“应用集群与负载均衡”实验。
1. 连续两次增加实例，得到 `app-1`、`app-2` 和 `app-3`。
1. 将 `app-3` 性能调整为 30%，确认有效容量变为 30。
1. 保持“真实请求流”停止，不生成流量。
1. 在集群控制区把负载均衡模式切换为“自适应”。
1. 观察状态先显示“自适应调整中”，再显示“自适应权重已稳定”。
1. 确认容量 `100:100:30` 在 10 秒内收敛为权重 `10:10:3`。
1. 发送真实请求批次，确认请求仍经过实验网关并由实际应用实例处理。
1. 切回“固定”模式，确认手动权重编辑器重新出现。
1. 将 `app-3` 性能改为 40%，确认最后权重 `10:10:3` 不再自动变化。
1. 结束实验并确认受管容器、网络、Nginx 片段和实验数据库被清理。

## 预期行为

* 无流量时仍根据有效容量收敛；
* `100:100:30` 约分为 `10:10:3`；
* 当前权重已经等于目标时不 reload Nginx；
* 扩缩容或性能变化会重新开始连续 3 次稳定采样；
* 切回固定模式后保留最后成功权重；
* 自动权重操作不刷新实验空闲时间；
* 自动权重操作不覆盖页面中的最近用户操作；
* 总负载超过集群容量时，页面说明权重无法创造容量；
* Nginx 应用失败时保留上一份有效配置和数据库权重，并按退避策略重试。

## 自动化验证

```powershell
go test ./...
go vet ./...
npm --prefix web test
npm --prefix web run build
npm --prefix web run test:e2e
docker compose config --quiet
```

Playwright 的“adaptive weights converge without generated traffic”用例覆盖三实例扩容、
30% 性能调整、无流量收敛、切回固定模式和最后权重保持。
平台重启恢复用例默认跳过，可通过以下命令单独执行：

```powershell
$env:RUN_PLATFORM_RESTART = '1'
npm --prefix web run test:e2e -- --grep "adaptive mode recovers"
```
