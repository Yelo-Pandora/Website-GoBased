# 应用与数据分离

一家网店准备在周五晚上更新商品搜索规则，同一时间数据库还要执行备份。
应用发布会占用处理器和磁盘，备份也在持续读取数据，两项工作放在一台机器上时很容易互相拖慢。
团队想频繁调整页面和业务规则，却不愿每次发布都碰存放商品与订单的机器。

把应用和数据库放到不同运行单元，先解决这层牵连。
应用负责接收请求和处理业务，数据库专心保存数据，两边通过内部网络通信。

## 请求多走了一段路

用户查询商品时，请求先到应用。
应用检查商品编号、分页范围和访问条件，然后从连接池取出一条数据库连接，通过内部网络发送查询。
数据库找到商品后返回记录，应用整理字段，再把结果交给用户。

单机里的函数调用很快，跨运行单元后多了一次网络往返。
网络可能变慢、短暂断开，也可能出现应用能运行但暂时联系不到数据库的情况。
应用需要设置合理的等待时间，避免一个迟迟没有结果的查询长期占住请求和连接。

连接池也要控制大小。
连接太少时，大量商品查询会在应用里排队，数据库明明还有余量却收不到请求。
连接太多时，每个应用都占住一批连接，数据库要花内存维护它们，真正执行查询的资源反而变少。
扩容应用之前，团队要把实例数量和每个实例的连接上限一起算进去。

> 实验衔接：在实验中，可通过“创建实验”操作加载应用与数据分离的固定场景配置，后端 Orchestrator 会创建 Lab App、接入共享 MySQL 并同步 Nginx 路由，从页面拓扑中观察请求链路跨越应用和数据库边界的效果。

## 发布和资源边界清楚了

应用与数据库分开后，两边可以按自己的节奏调整。
商品查询增加时，团队可以先给应用增加处理能力。
商品数据变多时，数据库更需要内存、磁盘和合适的索引，这些工作不必和页面发布绑在一起。

发布牵涉的范围缩小了。
替换应用只影响请求处理单元，数据仍留在数据库里。
数据库备份可以选择业务较轻的时间执行，不用跟着每次应用更新重新安排。
应用发布失败时，团队回退应用版本即可，通常不需要搬动商品和订单数据。

权限边界随之变得清楚。
应用账号只拿到业务所需的查询和写入能力，建库、改账号等管理操作留在受信环境。
数据库也不必向公网开放，内部网络只允许经过批准的应用访问。

> 实验衔接：在实验中，可通过“重置”操作重新应用场景配置，后端 Orchestrator 只重建该用户的 Lab App 和路由资源，并同步保留隔离的 MySQL 实验数据，从操作记录中观察应用生命周期与数据生命周期分离的效果。

## 网络会带来新的失败方式

应用和数据库都正常运行，请求仍可能在它们之间丢失。
商品查询遇到超时，应用可以在受控条件下再次读取，因为重复读取通常不会改变数据。
订单写入更麻烦。
数据库已经保存订单，但成功响应在返回途中丢了，应用看到的只有超时。
直接重试可能写出两份相同订单。

这类情况需要唯一操作标识和状态记录。
应用重试时，数据库先确认同一操作是否已经完成，再决定返回原结果还是继续处理。
后续实验会沿用这种幂等思路，避免网络抖动把一次用户操作放大成多次写入。

等待时间也不能一味拉长。
超时过短会把正常的慢查询当成失败，超时过长则让请求和连接一直被占用。
团队要结合正常响应时间、用户能等待多久和失败后的处理方式来选择边界。

> 实验衔接：在实验中，可通过“结束”后再次“新建实验”修改实验运行状态，后端 Platform API 使用唯一操作标识同步 Orchestrator 的销毁与创建结果，从操作记录中观察重复生命周期请求被幂等处理的效果。

## 数据库仍是共享依赖

职责分开以后，数据库仍承接所有商品和订单请求。
应用可以增加实例，数据库容量却不会跟着自动增长。
查询缺少索引、连接数失控或磁盘变慢时，前面的多个应用会一起排队。

这也是观察指标需要分层的原因。
应用响应变慢时，要继续查看连接等待、数据库查询时间和磁盘状态，不能只盯着应用自身的处理器占用。
请求跨过网络边界后，排查问题需要把两边的请求标识和时间记录对应起来。

共享数据库并没有失去价值。
在数据规模仍可控的阶段，它能保持一致的数据来源，避免团队过早处理数据复制和多库协调。
等到数据库确实成为长期瓶颈，再讨论读写分离、分片或其他存储方案会更稳妥。

> 实验衔接：在实验中，可通过刷新实验快照操作读取当前固定场景配置，后端 Platform API 会同步 Lab App、共享 MySQL 与 Nginx 网关的资源状态，从拓扑中观察数据库仍作为独立共享依赖的效果。

## 在实验里观察什么

等编排阶段完成后，平台会为用户创建一个应用实例和一套隔离的实验数据。
商品查询将真实经过内部网络访问共享 MySQL，页面会展示应用身份、请求路径、连接结果和返回数据。

这个阶段仍只有一个应用实例。
它解决了应用发布、资源使用和数据库管理混在一起的问题，应用单点故障仍然存在。
下一门课程会在这条请求路径前加入内部负载均衡，并把请求分给多个应用实例。

> 实验衔接：在实验中，可通过“创建实验”和“重置”操作切换资源生命周期配置，后端 Orchestrator 会同步单个 Lab App、共享 MySQL 和 Nginx upstream 的状态，从拓扑、状态标签和操作记录中观察单应用架构边界的效果。
