# 应用集群与负载均衡

促销开始后，商品详情请求从每秒几次涨到几十次。
一台 Go 应用的队列越来越长，团队加了第二台应用，却发现用户还是只会访问原来的入口。

多一台机器只是增加了处理能力。
系统还需要一个统一入口，把请求交给当前可以工作的实例。
负责这件事的组件叫负载均衡器，本平台使用 Nginx。

## 请求怎样进入集群

用户只访问一个地址。
请求到达 Nginx 后，Nginx 查看可用实例和分配规则，选出一台 Lab App，再把请求转发过去。
应用读取共享 MySQL，响应沿原路回到用户。

连续八个请求到来时，实例 A 和实例 B 可能各收到四个。
实例 B 暂时退出后，Nginx 应当停止向它发送新请求。
健康检查确认 B 恢复后，它才会重新加入可用列表。

应用实例还要共享正确的数据和会话信息。
如果登录状态只存在实例 A，下一次请求落到实例 B 时，用户就会像突然退出了一样。

> 在实验中，点击 `增加实例`，Orchestrator 会创建新的 Lab App，并把它加入 Nginx upstream。
> 拓扑和请求流会显示后续商品请求开始落到多台实例。

## 轮询适合什么情况

轮询会按顺序选择实例。
A 接一个，B 接一个，然后再回到 A。

几台机器性能接近，请求耗时也差不多时，轮询简单而且容易检查。
如果 B 因磁盘或外部依赖变慢，Nginx 仍会给它相近数量的请求，B 的队列便可能越积越长。

> 保持两台实例使用相同权重，再点击 `发送一批`，可以看到请求大致轮流进入不同实例。
> 请求数量较少时，短时间结果不一定刚好各占一半。

## 权重怎样改变流量份额

加权轮询允许每台实例使用不同份额。
如果 A 的处理能力约为 B 的两倍，可以给 A 更高权重，让它接到更多请求。

权重只表达当前的分配计划，不会测量机器性能。
B 后来变慢，旧权重仍会继续生效，除非用户或控制器重新调整。

权重也不能保证每个短时间窗口都完全符合比例。
请求数量、处理时间和实例恢复时刻都会带来偏差。

> 在实验中，修改实例行里的权重，再点击 `应用权重`。
> Platform API 会校验配置并更新 Nginx，后续请求的实例命中数会逐渐体现新的份额。

## 其他分配方法在解决什么

IP 哈希会根据用户来源选择实例，同一来源通常会落到同一台机器。
它能保持一定黏性，但公司网络或移动运营商可能让许多用户共用一个出口地址，流量仍会偏向某台实例。

最少连接会选择当前连接较少的实例。
请求耗时差异较大时，它比固定轮询更容易避开正在处理长任务的机器。
连接少不代表 CPU 和数据库访问一定空闲，所以它仍然只是一个判断依据。

响应时间策略会参考近期速度。
某台实例连续变慢后，入口可以少给它一些请求。
短暂抖动很常见，调整太频繁会让流量在实例之间来回摆动。

本平台重点演示固定权重和自适应权重。
其他方法用于帮助你理解，负载均衡策略总是在有限信息下做选择。

> 当前实验没有 IP 哈希和最少连接开关。
> 你可以用固定权重制造明确的流量差异，再和自适应模式的调整过程比较。

## 健康和容量为什么要分开看

健康检查回答实例还能不能接请求。
一个实例可以正常返回健康响应，同时已经积压了许多商品查询。

容量关注它还能处理多少工作。
本平台发送较低速率的请求，再用教学等效负载表示更大的业务压力，避免为了演示过载而占满宿主机 CPU。
页面会分别显示请求速率、等效负载和有效容量。

等效负载超过容量后，实验会记录队列增长和模拟丢弃。
这些数据用来说明分配策略，平台不会真的向外部制造同等规模的流量。

> 修改实例行里的 `处理速度` 后，Orchestrator 会按新参数重建目标 Lab App。
> 快照会更新容量，持续发送请求时，你可以观察队列和丢弃怎样变化。

## 固定权重为什么容易失配

固定模式会一直使用你设置的权重。
A 和 B 原本各接一半请求，B 的处理速度降低后，Nginx 仍按原比例转发。

B 的队列开始增长，A 可能还有余量。
页面中的流量份额和有效容量会出现明显差异。

这个现象能帮助你分清权重和性能。
权重是配置，性能是实例当前能做多少工作，两者不会自动保持一致。

> 先用 `应用权重` 固定流量比例，再降低某台实例的处理速度。
> 请求流、队列和丢弃计数会显示固定配置怎样把过多请求继续交给慢实例。

## 自适应权重为什么不会立刻跳动

自适应模式会读取实例容量和一段时间内的稳定负载，再计算目标权重。
控制器会等待变化持续一会儿，才减少发往慢实例的请求。

两次调整之间还会留出冷却时间。
这样上一轮配置有时间产生结果，也能避免一次短暂抖动引发连续改权重。

B 恢复后，权重同样会逐步增加。
刚启动的实例若马上接到大量请求，缓存和连接还没准备好，反而可能再次变慢。

Nginx 配置应用失败时，系统会保留上一份可用配置。
一次控制器调整不应切断整个实验入口。

> 点击 `自适应` 后，控制器会根据稳定负载更新目标权重，并同步到 Nginx。
> 页面会显示收敛状态、目标权重和实际命中比例，你可以看到调整需要时间。

## 调整权重为什么不能解决总容量不足

权重只能决定压力放在哪里，不能增加处理能力。
所有实例合起来只能处理每秒四十个请求时，入口收到六十个，怎样分配都会有一部分排队或失败。

团队需要增加实例、恢复慢实例的性能，或者限制进入系统的流量。
负载均衡能减少浪费，但不能凭空创造容量。

> 在相同实例数量下切换 `固定` 和 `自适应`，可以比较两种配置怎样移动流量。
> 当总等效负载超过集群容量时，两种模式都会出现队列或丢弃。
